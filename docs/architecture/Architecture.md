# Architecture: Personal IELTS Learning Dashboard
PRD: docs/business/PRD.md
Last updated: 2026-07-30

## Overview
The full-stack architecture per `docs/adr/2026-07-29-fullstack-vercel-claude-architecture.md` is built and passing (143 backend / 105 frontend tests): an Angular single-page frontend that talks only to a FastAPI backend over a REST API; the backend is the sole owner of the Postgres database and the sole caller of any AI provider or Speech-to-Text service. No frontend code ever holds a database connection or an AI provider API key. It has been verified running end-to-end locally (backend on Postgres in Docker, frontend proxying `/api` to it) but has **not yet been deployed** to Vercel/Neon — see Known Constraints. This revision also reflects the PRD revision-3 pivot from a self-directed progress tracker to an AI-generated daily lesson engine: two new epics (Reading, Listening practice generation) and one new integration (Text-to-Speech) join the previously-built set.

## Components
| Component | Responsibility | Serves epics |
|---|---|---|
| Angular Frontend | Renders all screens, collects learner input, calls the backend REST API through a shared `ApiClient`. Owns no persistent data and never talks to the database or an AI provider directly. | All epics (presentation layer) |
| FastAPI Backend | Owns all business logic and validation; the only component allowed to talk to the database, the AI Provider Layer, the Speech-to-Text service, or (once built) the Text-to-Speech service. Exposes the REST API the frontend calls. | All epics |
| Access Protection module (backend) | Gates every API request behind a single-learner login check (`require_learner` FastAPI dependency) using a signed, HttpOnly session cookie; rejects unauthenticated access to any study data or submission. Mechanism decided and implemented — see Cross-Cutting Decisions. | Epic-6 |
| Daily Lesson Plan module (backend + DB tables) | Decides each day's practice focus across all four skills, pulling due items from the Vocabulary and Mistake Notebook modules to personalize; presents the daily overview. Supersedes the prior "Study Plan" module's fixed 180-day plan/task model — that implementation still exists in code (`study_plan` backend module, `study-plan` Angular module) but its data model predates this reframing and is expected to be substantially reworked when this epic's own spec/plan is written. | Epic-1 |
| Vocabulary module (backend + DB tables) | Owns vocabulary entries and the spaced-repetition schedule; now also a personalization input to the Daily Lesson Plan module. | Epic-2 |
| Mistake Notebook module (backend + DB tables) | Owns individual mistake records and their categorization; now also a personalization input to the Daily Lesson Plan module. | Epic-3 |
| Practice & Progress module (backend + DB tables) | Aggregates recorded practice results (auto-scored Reading/Listening from Epic-9/10, AI-graded Writing/Speaking band estimates from Epic-7/8, plus manually-logged results) and derives trend views. | Epic-4 |
| Reading Practice module (backend + DB tables) | Generates a Reading passage and comprehension questions via the AI Provider Layer, stores them, and scores the learner's answers objectively on submission. Does not exist in code yet. | Epic-9 |
| Listening Practice module (backend + DB tables) | Generates a Listening script and comprehension questions via the AI Provider Layer, converts the script to audio via the Text-to-Speech integration, stores both, and scores the learner's answers objectively on submission. Does not exist in code yet. | Epic-10 |
| Data Export module (backend) | Reads across all of one learner's tables — including generated Reading/Listening/Writing/Speaking content once Epic-9/10 exist — and serializes them into one portable export file, on demand. | Epic-5 |
| AI Provider Layer (backend abstraction) | Defines a provider-agnostic interface (`evaluate_writing()`, `evaluate_speaking()`, `generate_quiz()`, `chat()`); `ClaudeProvider` is the production implementation, `LocalAIProvider` a zero-cost deterministic implementation for local dev, `FakeAIProvider` a test double — selected via an `AI_PROVIDER` environment variable so no calling code depends on Claude specifically. `generate_quiz()` currently returns a flat list of question strings and is not yet called by any router; it predates this revision and is not shaped for Epic-9/10's needs (a passage/script plus questions plus an answer key for objective scoring) — extending it vs. adding dedicated methods is an open decision for those epics' `/spec:plan`, not resolved here. | Epic-1, Epic-7, Epic-8, Epic-9, Epic-10 |
| Speech-to-Text integration (backend) | Converts a Speaking submission's audio into a transcript before it reaches the AI Provider Layer; implemented as a `SpeechToText` protocol with a swappable adapter (`LocalDemoSpeechToText` for dev), a separate external service, not the AI provider itself. | Epic-8 |
| Text-to-Speech integration (backend) | Converts a Listening module's generated script into audio the learner can play. Does not exist in code yet; the intended shape mirrors the existing Speech-to-Text integration exactly — a `TextToSpeech` protocol with a swappable local-demo adapter behind it, with a real vendor selected later without changing callers. Vendor choice is an open decision for Epic-10's `/spec:plan`. | Epic-10 |
| PostgreSQL (database) | The system of record for all learner data, reached only from the backend via SQLAlchemy models, with schema changes managed through Alembic migrations. Currently a local Docker Postgres instance for development; Neon is the intended managed instance for deployment but that migration has not happened yet — see Known Constraints. | All epics (shared persistence) |

## Key Data Flows
- General CRUD (Vocabulary, Mistakes, Progress, and the current Study Plan module): Angular calls a REST endpoint → FastAPI validates the request through the Access Protection module → the relevant backend module reads/writes Postgres via SQLAlchemy → response returns to Angular.
- Daily lesson generation (Epic-1): learner opens the daily overview → FastAPI's Daily Lesson Plan module reads due vocabulary (Epic-2) and recent mistake patterns (Epic-3) → derives today's personalization focus (once, cached — not regenerated on every view, per PRD cost constraint) → triggers/links to Reading (Epic-9), Listening (Epic-10) generation and supplies the day's Writing/Speaking prompt to Epic-7/8.
- Reading/Listening generation and scoring (Epic-9/10): Daily Lesson Plan module requests a passage or script for today's focus → FastAPI calls the AI Provider Layer (`generate_quiz()` or its Epic-9/10 successor) → for Listening, the resulting script is also sent through the Text-to-Speech integration to produce playable audio → the generated exercise and its answer key are stored → learner submits answers → FastAPI scores them objectively against the stored answer key (no AI call needed at scoring time) → the result is stored and surfaced to the Practice & Progress module (Epic-4) and, if wrong, offered as a candidate entry to the Mistake Notebook (Epic-3).
- Writing evaluation: learner responds to a prompt (daily-generated via Epic-1, or ad-hoc) in Angular → FastAPI receives it, builds the evaluation prompt, and calls `AIProvider.evaluate_writing()` (routed to `ClaudeProvider` in production) → the structured JSON result (band scores, strengths, weaknesses, sentence-level corrections) is stored in the writing-submissions table → returned to Angular for display.
- Speaking evaluation: learner responds to a prompt (daily-generated via Epic-1, or ad-hoc) with a recording → FastAPI sends the audio to the Speech-to-Text integration to obtain a transcript → FastAPI calls `AIProvider.evaluate_speaking()` with the transcript → the structured JSON result is stored in the speaking-submissions table, tracked through explicit status steps (submitted → transcribing → transcribed → evaluating → evaluated) to stay within serverless execution limits → returned to Angular. Pronunciation is always returned as "Not Assessed" until a dedicated speech-assessment capability is added (PRD Out of Scope).
- Data export: learner requests an export in Angular → FastAPI (Access Protection already applied) queries every table scoped to that learner, serializes the result into one portable file, and returns it for download — no data outside that learner's own rows is ever included.
- Authentication: learner submits a password in Angular → FastAPI's Access Protection module verifies it against the single stored hash, applies rolling IP-based lockout, and on success issues a signed session cookie → Angular's HTTP interceptor attaches that cookie to every subsequent API call → FastAPI rejects any request without a valid one, for every module above, with sliding 30-day expiry reissued once under 7 days remain.

## Cross-Cutting Decisions
- **Backend framework & ORM**: FastAPI with SQLAlchemy models and Alembic-managed migrations. Per `docs/adr/2026-07-29-fullstack-vercel-claude-architecture.md`.
- **Data storage**: PostgreSQL is the single system of record, reachable only from the backend (Docker locally today, Neon intended for deployment). Per the same ADR. Per-epic table schemas are not decided here — each epic's own `ImplementationPlan.md` defines its tables; Epic-9/10 have not been planned yet.
- **AI provider**: a swappable `AIProvider` interface with `ClaudeProvider` as the production implementation, `LocalAIProvider` for zero-cost local dev, and `FakeAIProvider` for tests, selected by an `AI_PROVIDER` environment variable; no other backend code depends on Claude specifically. Per the same ADR and `docs/adr/2026-07-29-ai-provider-interface-shape.md`. Epic-9/10's exercise-generation method shape is not yet decided (see AI Provider Layer row above).
- **Secrets**: the AI provider API key and the database connection string exist only as backend environment variables (Vercel Environment Variables in deployment); the frontend never receives them and never calls the AI provider or database directly.
- **Deployment**: both the Angular frontend and the FastAPI backend are designed to deploy to Vercel, with Neon Postgres as a separately managed service — per the same ADR — but this has not been executed yet; see Known Constraints.
- **Auth mechanism**: decided and implemented — a stateless, signed, HttpOnly session cookie (`itsdangerous` `URLSafeTimedSerializer`), bcrypt password hash, 30-day sliding expiry, rolling IP-based lockout persisted in Postgres (not in-memory, since Vercel serverless has no shared memory). Per `docs/adr/2026-07-29-signed-cookie-session-auth.md`.
- **Text-to-Speech (open)**: Epic-10 needs a way to turn a generated Listening script into audio. The integration boundary (a swappable protocol mirroring `SpeechToText`) is decided here; the actual vendor is not — record via a dedicated ADR when Epic-10's plan is written.

## Known Constraints / Technical Debt
- **Not yet deployed.** Everything above is built and tested against a local Docker Postgres instance and run locally (`ng serve` + `uvicorn`); moving to Neon + Vercel is a real remaining step (environment variables, Neon connection pooling behavior under serverless, Vercel build config for both apps), not yet attempted.
- **Vercel serverless execution limits**: addressed for Speaking (Epic-8) via explicit async status-tracked processing (`docs/adr/2026-07-29-speaking-async-step-tracked-processing.md`) so no single request chains Speech-to-Text and AI evaluation synchronously. Epic-10 (Listening generation, which similarly chains an AI call and a Text-to-Speech call) should evaluate whether it needs the same pattern during its own plan — not assumed here either way.
- **Real operating costs** (Neon, Vercel, AI API usage, and now Text-to-Speech for Epic-10) — per PRD constraints, prefer free/hobby tiers where available; each day's generated content is produced once and reused, not regenerated per view, and Writing/Speaking evaluation happens only on explicit learner submission.
- **The Daily Lesson Plan module (Epic-1) is a rework, not a clean slate.** A working "Study Plan" implementation already exists (fixed 180-day plan/checklist model, `study_plan` backend module + `study-plan` Angular module, 10/10 tasks complete) built against the now-superseded spec. Epic-1's own `/spec:plan` needs to decide how much of that code is adapted vs. replaced — not decided here.
- **Per-epic database schemas for Epic-9/10 are not yet designed.** This document establishes the shared Postgres/SQLAlchemy data layer and the Text-to-Speech integration shape; the actual tables and AI Provider method shapes belong in those epics' own `ImplementationPlan.md`.
